# اصول UX و طراحی صفحات

سند مرجع: `MD-UX-001` · نسخه ۱.۰ · مالک: مهندس UX · هم‌نویسنده: روانشناس شناختی

---

## ۱. اصل حاکم

> کاربر نباید احساس کند با حسابداری کار می‌کند. او کار روزانه‌اش را ثبت می‌کند؛ حسابداری، نتیجه است.

| کاربر | جمله‌ای که باید بگوید | جمله‌ای که نباید بگوید |
|---|---|---|
| اپراتور باسکول | «وزن را زدم، قبض چاپ شد.» | «اول باید سند بزنم؟» |
| انباردار | «بار را انتقال دادم.» | «مرکز هزینه چیست؟» |
| فروشنده | «فاکتور را دادم و صافی‌اش را کسر کردم.» | «بستانکار حساب دریافتنی…» |
| حسابدار | «سند خودکار درست است، کنترل کردم.» | «همه‌چیز باید دستی ثبت شود.» |

## ۲. پنج قانون طلایی UI

| قانون | معنی | مثال |
|---|---|---|
| **بدون صفحه‌پشت‌صفحه** | هر کار در همان صفحه | ثبت مشتری در Flyout داخل فاکتور |
| **بدون اسکرول طولانی** | صفحه اصلی، بدون اسکرول عمودی در ۱۰۲۴×۷۶۸ | فرم فاکتور سه‌ناحیه‌ای |
| **بدون فرم سنگین** | حداکثر ۷ فیلد در نمای اول؛ بقیه در «بیشتر» | باسکول: وزن، سبد، افت |
| **PopUp Smart / Flyout / Slide Modal / Floating Window** | لایه‌های سبک به‌جای صفحه جدید | جزئیات ردیف در Slide Modal |
| **همیشه یک راه بازگشت** | Esc، دکمه بستن، بازگشت بدون از دست دادن داده | پیش‌نویس خودکار |

## ۳. الگوهای تعامل استاندارد

| الگو | کاربرد | قاعده |
|---|---|---|
| **Flyout** (۳۲۰–۴۸۰px از راست) | ایجاد/ویرایش موجودیت کوچک | بعد از ذخیره، بسته می‌شود و مقدار در فرم اصلی انتخاب می‌شود |
| **Slide Modal** (۶۰٪ عرض) | فرم متوسط، جزئیات ردیف | با `Esc` بسته؛ داده حفظ |
| **Floating Window** (قابل جابه‌جایی) | کار موازی (مثلاً فهرست بدهی‌ها هنگام ثبت پرداخت) | چند پنجره هم‌زمان مجاز |
| **Command Palette** (`Ctrl+K`) | جست‌وجو و اجرای دستور | فاکتور، مشتری، حساب، «فاکتور جدید» |
| **Smart Popup** | انتخاب‌های چندگزینه‌ای، تأیید | حداکثر ۳ دکمه |
| **Drawer پایین (موبایل)** | فیلترها و جزئیات | swipe to close |

### ۳.۱ قاعده انتخاب الگو

```
آیا کاربر باید داده فعلی را ببیند؟
 ├─ بله → آیا کار جدید است یا مرجع؟
 │         ├─ ایجاد موجودیت کوچک → Flyout
 │         ├─ جزئیات/ویرایش → Slide Modal
 │         └─ کار موازی → Floating Window
 └─ خیر → آیا کار سنگین و مستقل است؟
           ├─ بله → صفحه کامل (فقط برای فهرست‌ها و گزارش‌ها)
           └─ خیر → Popup
```

## ۴. چیدمان استاندارد صفحه

```
┌──────────────────────────────────────────────────────────────────────────────┐
│  [لوگو]  ⊕  │  داشبورد  عملیات  خرید  فروش  باسکول  انبار  مالی  ...  │ 🔔۳ ? 👤 │
├──────────────────────────────────────────────────────────────────────────────┤
│  ناوبری مسیر: فروش › فاکتورها › فاکتور S14-002381        [فیلترها] [خروجی]   │
├──────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│   ناحیه اصلی (بدون اسکرول در صفحه فرم؛ جدول‌ها اسکرول داخلی دارند)            │
│                                                                              │
├──────────────────────────────────────────────────────────────────────────────┤
│  نوار وضعیت: 🟢 آنلاین · آخرین همگام‌سازی ۱۲ ثانیه پیش · کاربر: مریم · ۰۹:۴۱   │
└──────────────────────────────────────────────────────────────────────────────┘
```

| ناحیه | قواعد |
|---|---|
| هدر | ثابت، ۶۴px؛ ⊕ در مرکز؛ وضعیت اتصال همیشه دیده شود |
| ناوبری | حداکثر ۱۰ آیتم سطح اول؛ بقیه در «بیشتر» |
| ناحیه اصلی | یک کار اصلی در هر صفحه؛ چند کار = تب داخلی |
| نوار وضعیت | اتصال، صف همگام، کاربر، ساعت، نسخه |

## ۵. فرم‌ها

| قاعده | جزئیات |
|---|---|
| ترتیب فیلدها | از «چه کسی» → «چه چیزی» → «چقدر» → «چه زمانی» → «توضیح» |
| فیلد اجباری | با `*` و رنگ متفاوت؛ اما بهتر: پیش‌فرض هوشمند تا اجباری کم شود |
| اعتبارسنجی | زنده، کنار فیلد، بدون مودال خطا |
| ذخیره خودکار | پیش‌نویس هر ۲۰ ثانیه؛ بازیابی پس از قطع |
| محاسبات | زنده، بدون دکمه «محاسبه» |
| جمع‌ها | همیشه قابل مشاهده؛ چسبیده به پایین فرم |
| دکمه اصلی | یکی؛ راست‌چین؛ `Enter` = دکمه اصلی |
| انصراف | `Esc`؛ اگر تغییر ذخیره‌نشده باشد، تأیید کوتاه |
| حالت فقط‌خواندنی | بعد از ثبت: فیلدها خاکستری، نوار «ثبت‌شده — غیرقابل ویرایش» |

### ۵.۱ الگوی «جدول ردیف‌ها»

- افزودن ردیف با `F7` یا دکمه `+`.
- ویرایش درجا؛ `Tab` بین سلول‌ها.
- حذف با `Delete` + Undo ۵ ثانیه‌ای.
- ردیف‌های نامعتبر، با رنگ و آیکن، نه مودال.
- ردیف‌های تکراری، هشدار قبل از افزودن.

## ۶. کاهش خطای اپراتور (نگاه روانشناختی)

| خطای رایج | علت شناختی | راهکار طراحی |
|---|---|---|
| جابه‌جایی وزن پر و خالی | دو فیلد مشابه پشت سر هم | تفکیک بصری، برچسب بزرگ، تأیید هوشمند (وزن دوم باید کمتر باشد) |
| اشتباه در تاریخ | ورودی آزاد | پیش‌فرض امروز، ماسک ورودی، تقویم سریع |
| فراموشی کسر سبد | بار شناختی | محاسبه خودکار و نمایش تفکیک |
| انتخاب مشتری اشتباه | نام‌های مشابه | نمایش کد + شهر + مانده در لیست انتخاب |
| تأیید بدون خواندن | خستگی | متن دکمه، عمل‌محور: «ثبت فاکتور» نه «تأیید» |
| تکرار ثبت | کندی شبکه | Idempotency + دکمه غیرفعال پس از کلیک |
| ثبت در دوره اشتباه | نبود بازخورد | نمایش برجسته تاریخ سند در فرم |
| خطای عددی (یک صفر اضافه) | تایپ سریع | نمایش مبلغ به حروف کنار رقم |

**قاعده نمایش مبلغ به حروف:** برای مبالغ > ۱۰٬۰۰۰٬۰۰۰ ریال، حروف در زیر فیلد نمایش داده شود. این تنها راه جلوگیری از خطای صفر است.

## ۷. دسترس‌پذیری و دستگاه‌ها

| موضوع | قاعده |
|---|---|
| حداقل اندازه هدف لمسی | ۴۴×۴۴px (تبلت انبار) |
| کنتراست | ≥ ۴٫۵:۱ |
| کیبورد | همه کارها بدون ماوس ممکن (باسکول و دفتر) |
| فوکوس | قابل مشاهده و منطقی |
| RTL | همه کامپوننت‌ها RTL بومی، نه آینه‌سازی CSS |
| اعداد | فارسی در UI، لاتین در ورودی فنی |
| صفحه‌های هدف | ۱۰۲۴×۷۶۸ (حداقل)، ۱۳۶۶×۷۶۸ (اصلی)، ۱۹۲۰ (گزارش) |
| موبایل | کارت‌محور، ناوبری پایین، فرم تک‌ستون |

## ۸. بازخورد سیستم

| حالت | نمایش |
|---|---|
| بارگذاری | Skeleton (نه اسپینر تمام‌صفحه) |
| موفقیت | توست سبز ۳ ثانیه‌ای با لینک به سند («فاکتور ثبت شد — مشاهده») |
| خطا | نوار قرمز بالای فرم + پیام فارسی + کد پیگیری |
| هشدار | زرد، قابل رد کردن |
| آفلاین | نوار خاکستری «حالت محلی — ۱۲ رکورد در صف» |
| عملیات طولانی | نوار پیشرفت با تخمین |

## ۹. واژه‌نامه UI (زبان کار، نه حسابداری)

| در سیستم حسابداری | در UI |
|---|---|
| بدهکار/بستانکار | «دریافتنی / پرداختنی» (یا حذف کامل) |
| سند حسابداری | «سند» (فقط در ماژول مالی) |
| آرتیکل/خط سند | «ردیف» |
| تفصیلی | «حساب جزئی» یا نام طرف حساب |
| مرکز هزینه | «واحد» |
| درآمد/هزینه | «فروش/خرید/هزینه» |
| حساب دریافتنی | «طلب از مشتری» |

## ۱۰. پذیرش

- [ ] کار اصلی هر صفحه در ≤ ۳ کلیک و ≤ ۲ اسکرول.
- [ ] هیچ فرم اصلی، در ۱۰۲۴×۷۶۸ اسکرول عمودی نداشته باشد.
- [ ] ثبت قبض باسکول فقط با کیبورد، ≤ ۴۵ ثانیه.
- [ ] آزمون قابلیت استفاده با ۳ کاربر واقعی (اپراتور، انباردار، فروشنده) با نرخ موفقیت ≥ ۹۰٪ بدون کمک.
- [ ] هیچ واژه حسابداری خام در UI کاربر عملیاتی دیده نشود.
- [ ] همه اجزا با کنتراست AA و پیمایش کیبورد.
