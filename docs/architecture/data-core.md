# هسته داده — Data Core Engine

سند مرجع: `MD-ARC-002` · نسخه ۱.۰ · مالک: معمار ERP · تأیید: حسابرس ارشد

> **اصل:** هیچ داده‌ای، از هیچ منبعی (فرم، اکسل، بانک، باسکول، موبایل، API خارجی) بدون عبور از این هسته وارد سیستم نمی‌شود.
> هسته داده، «لوله مشترک» است: اعتبارسنجی ← نرمال‌سازی ← هویت ← کنترل دسترسی داده ← ثبت ← رویداد ← سند ← ردیابی.

---

## ۱. مسئله‌ای که حل می‌کند

بدون هسته داده، در سه ماه اول این‌ها رخ می‌دهد:
- فایل اکسل بانک با فرمت متفاوت، سه پیاده‌سازی متفاوت پیدا می‌کند.
- قبض باسکول در دو جدول با دو دقت متفاوت وزن ذخیره می‌شود.
- یک فاکتور ثبت می‌شود ولی سند حسابداری‌اش به دلیل خطای شبکه ساخته نمی‌شود.
- کد ملی با فاصله/خط تیره در چهار جا چهار شکل است.
- کسی نمی‌داند این عدد از کدام فایل و کدام کاربر آمده.

**هسته داده، این پنج شکاف را با یک مسیر واحد می‌بندد.**

## ۲. خط لوله (Pipeline)

```
 [منبع]
   ├─ فرم UI
   ├─ Import Studio (Excel/CSV بانک، اکسل مشتریان، اکسل موجودی)
   ├─ دستگاه باسکول (Serial/TCP)
   ├─ اپ موبایل / کلاینت آفلاین
   └─ API خارجی / Webhook
        │
        ▼
 ┌──────────────────────────────────────────────────────────────┐
 │ 1. ADMISSION     پذیرش: نوع سند، منبع، کاربر/دستگاه، مجوز    │
 │                  تولید correlation_id و idempotency_key      │
 ├──────────────────────────────────────────────────────────────┤
 │ 2. NORMALIZE     نرمال‌سازی: عدد، تاریخ شمسی، پلاک، کد ملی،   │
 │                  شبا، نام (فاصله/نیم‌فاصله)، واحد، ارز        │
 ├──────────────────────────────────────────────────────────────┤
 │ 3. IDENTIFY      هویت‌بخشی: تطبیق طرف حساب/کالا/حساب با       │
 │                  کد، کد ملی، شبا، بارکد، Mobile، نام دقیق     │
 │                  (نتیجه: MATCHED | NEW | AMBIGUOUS | REJECT)  │
 ├──────────────────────────────────────────────────────────────┤
 │ 4. VALIDATE      قواعد: DV-* ، BR-*، اجباری‌ها، بازه‌ها        │
 │                  (نتیجه: PASS | WARN | BLOCK)                │
 ├──────────────────────────────────────────────────────────────┤
 │ 5. ENRICH        پرکردن: قیمت روز، وزن سبد، نرخ ارز،          │
 │                  شرایط قرارداد، مانده، موجودی، اعتبار         │
 ├──────────────────────────────────────────────────────────────┤
 │ 6. SLOT          تخصیص شماره/شناسه، دوره مالی، وضعیت اولیه    │
 ├──────────────────────────────────────────────────────────────┤
 │ 7. COMMIT        ثبت اتمیک (سند + خطوط + حرکات انبار +         │
 │                  مانده‌ها + Posting + Outbox)                 │
 ├──────────────────────────────────────────────────────────────┤
 │ 8. PROPAGATE     انتشار رویداد: BI، نوتیفیکیشن، همگام‌سازی،   │
 │                  چاپ، پیامک                                   │
 ├──────────────────────────────────────────────────────────────┤
 │ 9. TRACE         ثبت مسیر کامل: منبع → نرمال‌سازی → تصمیم‌ها   │
 │                  (sys_data_trace)                             │
 └──────────────────────────────────────────────────────────────┘
        │
        ▼
   [سند ثبت‌شده + سند حسابداری + رویداد + ردیابی]
```

## ۳. مؤلفه‌های هسته

| مؤلفه | مسئولیت | اینترفیس |
|---|---|---|
| `AdmissionGate` | مجوز، محدودیت نرخ، تشخیص منبع، تولید Correlation | `IAdmission` |
| `Normalizer` | یکسان‌سازی انواع (عدد فارسی، تاریخ، پلاک، کد ملی، شبا، نام) | `INormalizer` |
| `IdentityResolver` | تطبیق یا ایجاد طرف حساب/کالا/حساب با قواعد Fuzzy کنترل‌شده | `IIdentityResolver` |
| `RuleEngine` | اجرای BR/DV، تولید WARN/BLOCK با پیام فارسی | `IRuleEngine` |
| `Enricher` | پرکردن مقادیر وابسته (فی روز، وزن سبد، نرخ ارز) | `IEnricher` |
| `DocumentSlot` | شماره‌گذاری، دوره، شعبه، وضعیت | `IDocSlot` |
| `UnitOfWork` | تراکنش اتمیک چند-موجودیتی | `IDataCore.CommitAsync` |
| `PostingEngine` | تبدیل رویداد به سند دوبل | `IPostingEngine` |
| `Outbox` | صف رویداد تضمین‌شده | `IOutbox` |
| `Tracer` | ثبت مسیر داده | `ITraceWriter` |

## ۴. قرارداد ورودی (Ingest Envelope)

همه منابع، یک پاکت واحد می‌سازند:

```json
{
  "envelope_id": "0192f3a1-8c...",
  "source": "IMPORT_EXCEL | FORM | DEVICE_SCALE | MOBILE | API",
  "source_ref": "bank-mellat-140407.xlsx#row:42",
  "doc_type": "BANK_STATEMENT_LINE",
  "operation": "CREATE | UPDATE | POST | VOID",
  "correlation_id": "c-7f3e...",
  "idempotency_key": "bnk:mel-4432:2026-10-09:45200000:8f2a",
  "actor": { "user_id": "...", "role": "ACCOUNTANT", "node_id": "SRV01" },
  "business_date": "2026-10-09",
  "payload": { "...": "داده خام منبع" },
  "options": { "dry_run": false, "auto_identify": true, "allow_new_party": false }

```

**نتیجه:**

```json
{
  "status": "COMMITTED | REJECTED | NEEDS_REVIEW | DRY_RUN_OK",

  "warnings": [ { "code": "BR-533", "message": "مرکز هزینه تعیین نشده" } ],
  "trace_id": "t-..."
```

## ۵. نرمال‌سازی (قواعد اجباری)

| نوع | قاعده | مثال ورودی → خروجی |
|---|---|---|
| عدد | حذف جداکننده، تبدیل ارقام فارسی/عربی، حذف «٬» و «,» و فاصله | `۱۲٬۵۰۰٬۰۰۰` → `12500000` |
| اعشار | نقطه اعشار؛ تبدیل `٫` و `,` در بستر عددی | `۱۸٬۴۵۰٫۵` → `18450.5` |
| تاریخ | الگوهای `YYYY/MM/DD`, `YY/MM/DD`, `DD-MM-YYYY`, سریال اکسل، متن فارسی | `1404/07/18` → `2026-10-10` |
| تاریخ اکسل | تبدیل سریال (epoch 1899-12-30) با تصحیح کبیسه | `45559` → `2024-09-20` |
| پلاک | حذف فاصله/خط تیره، تبدیل حروف فارسی به لاتین، یکسان‌سازی «ایران» | `۱۲ ب ۳۴۵ ایران ۱۱` → `12B345IR11` |
| کد ملی | حذف غیررقم، اعتبارسنجی رقم کنترل، صفر پیشرو | `۰۰۱۲۳۴۵۶۷۸` → `0012345678` |
| شبا | حذف `IR` و فاصله، بزرگ‌سازی، اعتبارسنجی طول ۲۴ | `ir 120 000...` → `120000...` |
| نام | یکسان‌سازی ی/ک عربی، حذف فاصله اضافی، نگه‌داشتن شکل نمایشی | `موسسه  آ.ب` → `موسسه آ.ب` |
| شرح | حذف فاصله اضافی، بریدن > ۵۰۰ کاراکتر با ثبت هشدار | — |
| واحد | نگاشت واحدهای محلی (کیلو/kg/کیلوگرم) به کد استاندارد | `کیلو` → `KG` |
| ارز | نگاشت ریال/تومان/IRT/IRR و اعمال نسبت | `۴۸٬۰۰۰ تومان` → `480000 IRR` |

**قاعده:** نرمال‌سازی روی **کپی** اجرا می‌شود؛ داده خام همیشه در `sys_data_trace.raw_payload` نگه داشته می‌شود برای حسابرسی.

## ۶. هویت‌بخشی (Identity Resolution)

ترتیب تطبیق برای طرف حساب:

| اولویت | کلید | نتیجه |
|---|---|---|
| ۱ | `code` دقیق | MATCHED |
| ۲ | `national_id` / `economic_code` | MATCHED |
| ۳ | `iban` (شبا) | MATCHED (با هشدار اگر چندطرفه) |
| ۴ | `mobile` نرمال‌شده | MATCHED با تأیید |
| ۵ | نام دقیق (پس از نرمال‌سازی) | MATCHED با تأیید |
| ۶ | نام مشابه (شباهت ≥ ۹۰٪) | AMBIGUOUS → نیازمند انتخاب |
| ۷ | هیچ | NEW (اگر مجاز) یا NEEDS_REVIEW |

**قاعده طلایی:** هسته داده **هرگز خودکار طرف حساب جدید نمی‌سازد** مگر `options.allow_new_party = true` و مجوز `core.party.create.auto` موجود باشد. در Import بانکی، پیش‌فرض «ایجاد نکن، پیشنهاد بده».

## ۷. کنترل اتمیک و Idempotency

```sql
-- تضمین عدم ثبت تکراری
CREATE TABLE sys_idempotency (
  key          varchar(120) PRIMARY KEY,
  operation    varchar(80)  NOT NULL,
  result_json  jsonb        NOT NULL,
  created_at   timestamptz  NOT NULL DEFAULT now(),
  expires_at   timestamptz
);
```

- کلید از ترکیب معنادار ساخته می‌شود (نه UUID تصادفی): `doc_type:source_ref:business_date:amount:hash`.
- تکرار درخواست با همان کلید → پاسخ ذخیره‌شده برگردانده می‌شود (۲۰۰، بدون ثبت دوباره).
- هر Import Batch یک `batch_id` دارد و همه ردیف‌های آن، کلید مستقل دارند.

**قواعد اتمیک:**
1. سند سرآمد + خطوط + Posting + Stock + Outbox = یک تراکنش.
2. شکست Posting = شکست کل (Rollback کامل).
3. اگر Outbox شکست خورد، تراکنش هم شکست می‌خورد (تضمین انتشار).

## ۸. ردیابی داده (Data Trace)

هر سند ثبت‌شده دارای مسیر کامل است:

| جدول | محتوا |
|---|---|
| `sys_data_trace` | `document_type`, `document_id`, `source`, `source_ref`, `raw_payload jsonb`, `normalized_payload jsonb`, `identity_decisions jsonb`, `rules_applied jsonb`, `actor`, `correlation_id`, `at` |
| `sys_status_history` | تغییر وضعیت‌ها با دلیل |
| `sys_audit_log` | تغییر فیلدها (Before/After) |
| `doc_attachment` | فایل منبع (اکسل اصلی، تصویر قبض، رسید) |

**قابلیت لازم:** از هر ردیف گزارش مالی، با ۳ کلیک به فایل منبع و کاربر و ساعت ورود برسیم. این پاسخ به «این عدد از کجا آمده؟» است.

## ۹. الگوی پلاگین منبع (Source Adapter)

هر منبع جدید، بدون تغییر هسته اضافه می‌شود:

```
ISourceAdapter {
  string SourceType { get; }
  Task<IngestEnvelope> ReadAsync(Stream input, AdapterContext ctx);
  Task<NormalizationReport> NormalizeAsync(IngestEnvelope env, INormalizer n);
}
```

| Adapter | ورودی | نکته |
|---|---|---|
| `FormAdapter` | JSON از UI | تطبیق مستقیم |
| `ExcelAdapter` | xlsx/csv | با Template برای نگاشت |
| `BankStatementAdapter` | xlsx/csv/pdf(متنی) | تشخیص بانک با اثر انگشت ستون‌ها |
| `ScaleAdapter` | TCP/Serial | پایداری وزن، فیلتر نوسان |
| `LegacyDbAdapter` | SQL Server/Access قدیمی | مهاجرت داده |
| `ApiAdapter` | JSON خارجی | Webhook |
