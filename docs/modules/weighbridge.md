# ماژول باسکول — قلب سیستم

سند مرجع: `MD-MOD-WB-001` · نسخه ۱.۰ · مالک: متخصص صنعت مرکبات · بازبین: مهندس شبکه، UX

> اگر باسکول درست کار نکند، هیچ‌چیز درست کار نمی‌کند. این ماژول باید در سرما، با دستکش، با نور کم و در صف کامیون، در **۴۵ ثانیه** کار را تمام کند.

---

## ۱. هدف و دامنه

| در دامنه | خارج از دامنه |
|---|---|
| ثبت توزین ورود و خروج، دو مرحله‌ای و یک‌مرحله‌ای | کنترل سخت‌افزاری توزین (کالیبراسیون قانونی) |
| محاسبه وزن سبد، افت بار، وزن خالص | تشخیص خودکار رقم مرکبات با دوربین (فاز بعد) |
| صدور قبض با QR/بارکد و چاپ | پرداخت بانکی در محل |
| صف و نوبت، ثبت دروازه | اتصال به دوربین پلاک‌خوان (اختیاری، فاز ۳) |
| اتصال به باسکول و نمایشگر LED | ترازوی کوچک آزمایشگاهی |
| آفلاین کامل و همگام‌سازی | — |

## ۳. فرآیند کسب‌وکار

### ۳.۱ ورود بار (خرید از باغدار) — دو مرحله‌ای

```
[دروازه]  پلاک + باغدار + نوبت
   │         ↓ wb_gate_log (IN)
   ▼
[باسکول]  وزن اول (پر)  ─ خواندن از دستگاه یا ورود دستی
   │         ↓ wb_ticket (status=DRAFT, gross_weight_kg)
   ▼
[باسکول]  تعداد و نوع سبد ← پیش‌فرض بر اساس قرارداد
   │         ↓ basket_tare_kg محاسبه خودکار
   ▼
[باسکول]  افت بار ← پیش‌فرض قرارداد باغدار (%)، قابل تغییر با دلیل
   │         ↓ waste_kg, net_weight_kg
   ▼
[باسکول]  پیش‌نمایش قبض + تأیید اپراتور
   │         ↓ status=WEIGHED  (چاپ قبض با QR)
   ▼
[انبار]   حواله ورود + تعیین سردخانه/اتاق + لات
   │         ↓ wb_ticket.warehouse_id, lot_id
   ▼
[دفتر]    فاکتور خرید (فی از قرارداد یا ورود دستی)
   │         ↓ status=PRICED → APPROVED → POSTED
   ▼
[خزانه]   تسویه نقد/چک/حواله → مانده باغدار صفر
```

### ۳.۲ خروج بار (فروش) — یک‌مرحله‌ای

```
[سفارش/فاکتور]  ← لینک اجباری (BR-311)
   ▼
[باسکول]  وزن پر (بار روی کامیون) → وزن خالی → وزن بار
   ▼
[باسکول]  کنترل با وزن فاکتور: اختلاف > ۰٫۵٪ → هشدار
   ▼
[باسکول]  چاپ قبض خروج + بارنامه
   ▼
[انبار]   خروج موجودی از لات مشخص
```

### ۳.۳ استثناها

| استثنا | رفتار |
|---|---|
| دستگاه باسکول قطع است | ورود دستی با دلیل + مجوز + امضای راننده (BR-310) |
| وزن دوم ثبت نشد و راننده رفت | قبض «باز» می‌ماند؛ هشدار پس از ۴ ساعت؛ مانع خروج کامیون |
| افت بار بیش از سقف | مسیر تأیید سرپرست |
| اختلاف وزن با فاکتور | پرچم بررسی، امکان اصلاح قبل از POSTED |
| ابطال قبض | فقط قبل از POSTED؛ پس از آن سند برگشتی |
| برق قطع شد | UPS + کلاینت آفلاین؛ قبض پس از بازگشت ثبت می‌شود (زمان واقعی حفظ می‌شود) |
| کامیون بیش از ظرفیت | هشدار اضافه‌بار (BR-316) |

```sql
CREATE TABLE wb_ticket (
  id uuid PRIMARY KEY,
  code varchar(32) NOT NULL,
  branch_id uuid NOT NULL REFERENCES core_branch(id),
  direction smallint NOT NULL,
  business_date date NOT NULL,
  vehicle_id uuid NOT NULL REFERENCES core_vehicle(id),
  driver_id uuid NOT NULL REFERENCES core_party(id),
  party_id uuid NOT NULL REFERENCES core_party(id),
  garden_id uuid REFERENCES core_garden(id),
  item_id uuid NOT NULL REFERENCES core_item(id),
  gross_weight_kg numeric(14,3) NOT NULL,
  tare_weight_kg numeric(14,3),
  vehicle_net_kg numeric(14,3) NOT NULL,
  basket_count int,
  basket_type_id uuid REFERENCES core_container_type(id),
  basket_tare_kg numeric(14,3) DEFAULT 0,
  waste_pct numeric(9,4) DEFAULT 0,
  waste_kg numeric(14,3) DEFAULT 0,
  net_weight_kg numeric(14,3) NOT NULL,
  scale_id uuid REFERENCES wb_device(id),
  is_manual_weight boolean NOT NULL DEFAULT false,
  manual_reason varchar(200),
  status smallint NOT NULL DEFAULT 0,
  created_by uuid NOT NULL,
  created_at timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT ck_wb_positive CHECK (net_weight_kg > 0),
  CONSTRAINT ck_wb_tare CHECK (tare_weight_kg IS NULL OR tare_weight_kg < gross_weight_kg),
  CONSTRAINT uq_wb_code UNIQUE (branch_id, code)
);
CREATE UNIQUE INDEX uq_wb_one_open_per_vehicle
  ON wb_ticket (vehicle_id)
  WHERE status IN (0,1);
```

## ۵. چرخه عمر

```
DRAFT ──(وزن دوم/تأیید)──► WEIGHED ──(فی)──► PRICED ──(تأیید)──► APPROVED ──(ثبت)──► POSTED
  │                          │                │                     │
  └──── VOID ────────────────┴──── VOID ──────┴──── VOID ───────────┴── REVERSED (سند برگشتی)
```

| انتقال | مجوز | اثر |
|---|---|---|
| DRAFT→WEIGHED | `wb.ticket.weigh` | چاپ قبض، ظهور در انبار |
| WEIGHED→PRICED | `wb.ticket.price` | آمادگی فاکتور |
| PRICED→APPROVED | `wb.ticket.approve` | قفل ویرایش وزن |
| APPROVED→POSTED | `wb.ticket.post` | سند خرید (JE-PUR-001) |
| هر → VOID | `wb.ticket.void` | دلیل اجباری، بدون اثر مالی |
| POSTED→REVERSED | `wb.ticket.reverse` | سند برگشتی و برگشت موجودی |

**قواعد تجربه:**

| قاعده | دلیل |
|---|---|
| وزن با فونت ≥ ۷۲px، وسط صفحه | خواندن از ۳ متری |
| همه‌چیز با کیبورد (`Enter` ثبت، `F2` دستی، `Tab` بعدی) | دستکش و سرما |

## ۷. اتصال به سخت‌افزار

| قطعه | پروتکل | جزئیات |
|---|---|---|
| باسکول (نشانگر وزن) | RS232/USB Serial, TCP | خواندن مداوم، تشخیص پایدار (۳ نمونه متوالی با اختلاف < ۰٫۲kg) |
| نمایشگر LED | Serial/Modbus | نمایش وزن و شماره نوبت برای راننده |
| چاپگر حرارتی | ESC/POS (۸۰mm) | چاپ خودکار قبض |
| چاپگر لیزری | Windows Printer | قبض A5 با QR |
| بارکدخوان | USB HID | اسکن قبض برای بازیابی |
| دوربین پلاک‌خوان | HTTP API | فاز ۳ |

**پایداری وزن:** وزن تنها زمانی پذیرفته می‌شود که در بازه ۲ ثانیه، ۳ نمونه با انحراف < ۰٫۲kg داشته باشد. وزن ناپایدار، دکمه تأیید را غیرفعال می‌کند.

## ۸. آفلاین و همگام‌سازی

| موضوع | تصمیم |
|---|---|
| ذخیره | SQLite محلی روی کلاینت باسکول + صف `sync_outbox` |
| شماره قبض | موقت با پیشوند گره: `1404-07-18-WB-01-0042`؛ در همگام‌سازی به شماره سراسری نگاشت می‌شود |
| چاپ | محلی؛ مستقل از شبکه |
| کدهای پایه | کش کامل (باغداران، کامیون‌ها، سبدها، قراردادها) با Pull دوره‌ای |
| تضاد | قبض هرگز ادغام نمی‌شود؛ اگر همان قبض در سرور هم هست (خطای نادر)، نسخه سرور نگه داشته و نسخه محلی به صف بررسی می‌رود |
| مدت پشتیبانی | حداقل ۸ ساعت قطعی، ۵۰۰ قبض در صف |

## ۱۴. پذیرش

- [ ] ثبت یک قبض کامل با کیبورد، در ≤ ۴۵ ثانیه و بدون ماوس.
- [ ] قطع شبکه، ۲۰۰ قبض ثبت و پس از اتصال، بدون تکرار و بدون شکاف شماره همگام شود.
- [ ] چاپ قبض با QR، با اسکن موبایل، همان قبض را باز کند.
- [ ] وزن ناپایدار، قابل تأیید نباشد.
- [ ] تغییر وزن استاندارد سبد، قبض‌های قبلی را تغییر ندهد.
- [ ] ابطال پس از ثبت، سند برگشتی بسازد و موجودی برگردد.
- [ ] گزارش روزانه، جمع وزن را با جمع قبض‌ها برابر نشان دهد (±۱ گرم).
