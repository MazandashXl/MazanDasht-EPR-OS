# ماژول مشتریان و CRM

سند مرجع: `MD-MOD-CRM-001` · نسخه ۱.۰ · مالک: مدیر محصول · بازبین: متخصص صنعت

---

## ۱. چرا CRM در یک سیستم مرکبات؟

در این صنعت، «مشتری» یک ردیف در دفتر نیست؛ یک رابطه با سه ویژگی است:

| ویژگی | پیامد طراحی |
|---|---|
| معامله روی اعتماد و تلفن انجام می‌شود | پیگیری تماس و تاریخچه گفت‌وگو، به‌اندازه فاکتور مهم است |
| صافی، حمل و کمیسیون، مذاکره‌ای است | باید تاریخچه توافق هر مشتری ثبت شود |
| چک برگشتی، فصلی و ناگهانی است | سابقه اعتباری باید در لحظه صدور فاکتور دیده شود |

---

## ۲. گروه‌های مشتری و چیدمان اختصاصی

| گروه | نیاز اطلاعاتی | چیدمان گزارش/فرم |
|---|---|---|
| **بارفروش** | فی روز، صافی، حمل، مانده، چک | صورت‌حساب با ریز کسورات؛ ستون صافی و حمل برجسته |
| **باغدار** | وزن قبض، افت، کیفیت، پرداخت | صورت‌حساب قبض‌محور؛ اولین ستون: قبض باسکول |
| **عمده‌فروش** | حجم، مبلغ، تسویه | چیدمان ساده: مبلغ و مانده |
| **صادرات** | ارز، اینکوترمز، مدارک | ستون ارز، شماره بارنامه، وضعیت مدارک |
| **خرده/متفرقه** | مبلغ، تسویه نقدی | چیدمان فشرده |

**قاعده:** چیدمان، بخشی از تنظیمات گروه است، نه کد. کاربر می‌تواند ستون‌ها را تغییر دهد.

## ۴. فرآیندها

### ۴.۱ چرخه عمر مشتری

```
سرنخ → مذاکره → اولین معامله → مشتری فعال → مشتری کلیدی → (ریزش)
```

| مرحله | اقدام سیستم |
|---|---|
| سرنخ | ثبت در CRM، یادآوری پیگیری |
| مذاکره | ثبت تعامل، پیش‌فاکتور |
| اولین معامله | ایجاد پروفایل مالی، سقف اعتبار اولیه |
| فعال | پیگیری خودکار عدم خرید > ۴۵ روز |
| کلیدی | پرچم، شرایط ویژه، گزارش سود |
| ریزش | دلیل، تلاش بازگشت |

### ۴.۲ پیگیری خودکار

| رویداد | اقدام |
|---|---|
| ۳۰ روز بدون خرید | وظیفه پیگیری برای مسئول |
| مانده > سقف | هشدار به فروش و مالی |
| چک سرسید | یادآوری قبل از سرسید |
| شکایت باز > ۴۸ ساعت | ارجاع به مدیر |
| کاهش ۳۰٪ خرید نسبت به ماه قبل | تحلیل و تماس |

### ۴.۳ شکایت

| نوع | نمونه | گردش |
|---|---|---|
| کیفیت | «بار له شده» | بررسی لات → عکس → تصمیم (تعویض/تخفیف/رد) |
| وزن | اختلاف وزن | بررسی قبض و فاکتور |
| تسویه | تأخیر در وصول | مالی |
| خدمات | تأخیر ارسال | عملیات |

هر شکایت به لات و فاکتور ارجاع می‌شود (ردیابی).
