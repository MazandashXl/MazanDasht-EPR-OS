# ماژول فروش و صافی مشتری

سند مرجع: `MD-MOD-SAL-001` · نسخه ۱.۰ · مالک: متخصص صنعت مرکبات · بازبین: حسابرس مالی

---

## ۱. هدف و دامنه

فروش در صنعت مرکبات، «مبلغ × تعداد» نیست. یک فاکتور واقعی مازندشت این‌طور است:

| ردیف | مقدار |
|---|---|
| محصول | پرتقال تامسون درجه یک |
| تعداد سبد | ۲۱۰ |
| نوع سبد | قرمز ۲٫۸ کیلو |
| وزن باسکول | ۱۷٬۵۰۰ کیلو |
| افت بار | ۲٪ |
| وزن خالص | ۱۶٬۶۵۰ کیلو |
| فی | ۳۲٬۰۰۰ تومان |
| مبلغ | ۵۳۲٬۸۰۰٬۰۰۰ تومان |
| **صافی** | ۰٫۷۵٪ |
| **حمل** | ۴٬۵۰۰٬۰۰۰ تومان |
| **کمیسیون** | ۰٫۵٪ |
| **بارگری** | ۱٬۲۰۰٬۰۰۰ تومان |
| **قابل پرداخت** | ۵۲۳٬۷۲۹٬۷۵۰ تومان |

این ماژول باید این جمله را بدون ماشین‌حساب و بدون اکسل انجام دهد، و در همان لحظه سند دوبل بسازد.

**در دامنه:** پیش‌فاکتور، سفارش، حواله، فاکتور، صافی/کسورات، برگشت، تسویه، کنترل اعتبار، تابلوی قیمت، پورسانت.
**خارج از دامنه:** فروش آنلاین B2C، درگاه پرداخت اینترنتی.

## ۳. فرمول صافی (مرجع)

```
gross_amount  = Σ line_amount
deduction_pct = Σ (base × rate/100)      برای PCT
deduction_fix = Σ (amount)                برای FIXED
net_payable   = gross_amount − deduction_pct − deduction_fix + addition_amount + vat + duty
```

**ترتیب اعمال:** بر اساس `sequence`. پیش‌فرض: `PURITY(10) → LOSS(20) → COMMISSION(30) → FREIGHT(40) → LOADING(50) → CARTON(60) → OTHER(99)`.

**قاعده:** همه کسور درصدی روی `gross_amount` (نه روی مبلغ کسور دیگر) محاسبه می‌شوند، مگر `calc_method = PCT_OF_NET` که صریحاً انتخاب شود. مبنای محاسبه همیشه در `base_amount` ذخیره می‌شود تا گزارش «چرا این عدد؟» ممکن باشد.

### مثال عددی کامل

| جزء | محاسبه | مبلغ (ریال) |
|---|---|---|
| مبلغ ناخالص | ۱۶٬۶۵۰ kg × ۳۲۰٬۰۰۰ | ۵٬۳۲۸٬۰۰۰٬۰۰۰ |
| صافی ۰٫۷۵٪ | ۵٬۳۲۸٬۰۰۰٬۰۰۰ × ۰٫۷۵٪ | ۳۹٬۹۶۰٬۰۰۰ |
| کمیسیون ۰٫۵٪ | ۵٬۳۲۸٬۰۰۰٬۰۰۰ × ۰٫۵٪ | ۲۶٬۶۴۰٬۰۰۰ |
| حمل | ثابت | ۴۵٬۰۰۰٬۰۰۰ |
| بارگری | ثابت | ۱۲٬۰۰۰٬۰۰۰ |
| **قابل پرداخت** | ۵٬۳۲۸٬۰۰۰٬۰۰۰ − ۱۲۳٬۶۰۰٬۰۰۰ | **۵٬۲۰۴٬۴۰۰٬۰۰۰** |

## ۴. فرآیند

```
[تابلوی قیمت روز] ──► [پیش‌فاکتور] ──► [سفارش (رزرو)] ──► [حواله/بارگیری] ──► [فاکتور] ──► [ثبت] ──► [تسویه]
                                                            │
                                          [کنترل موجودی/اعتبار]  [صافی]  [COGS]  [سند JE-SAL]
```

### گام‌ها و کنترل‌ها

| گام | کنترل | رفتار |
|---|---|---|
| قیمت | پیش‌فرض از تابلوی روز؛ تغییر > ۱۰٪ نیازمند دلیل | هشدار زرد |
| پیش‌فاکتور | اعتبار ۲۴ ساعت | خودکار منقضی |
| سفارش | رزرو موجودی؛ سقف اعتبار مشتری | رد/تأیید |
| حواله | انتخاب لات (FIFO پیشنهادی بر اساس تاریخ ورود) | قابل تغییر با دلیل |
| فاکتور | وزن خالص، فی، کسورات | پیش‌نمایش کامل |
| ثبت | موجودی، COGS، سند | اتمیک |
| تسویه | نقد/چک/تهاتر/تخفیف | مانده به‌روز |

## ۶. کنترل اعتبار

```
available_credit = credit_limit − (open_balance + overdue_cheques + unposted_orders)
if invoice.net_payable > available_credit:
     اگر کاربر مجوز override دارد → تأیید با دلیل
     وگرنه → رد با پیشنهاد: کاهش مبلغ / دریافت پیش‌دریافت / تأیید مدیر مالی
```

**منابع محاسبه:** مانده دریافتنی از `vw_party_balance` + چک‌های در جریان وصول + سفارش‌های تأییدنشده.

## ۱۳. پذیرش

- [ ] صدور فاکتور با ۲ ردیف و ۴ کسور، با کیبورد، در ≤ ۳ دقیقه.
- [ ] جمع مبلغ فاکتور = جمع خطوط؛ جمع کسور = جمع ریز؛ مانده = مبلغ − پرداخت.
- [ ] تغییر یک کسور، همه مبالغ را فوری و درست بازمحاسبه کند.
- [ ] فاکتور ثبت‌شده، سند حسابداری متوازن با COGS داشته باشد.
- [ ] عبور از سقف اعتبار، بدون مجوز، غیرممکن باشد.
- [ ] برگشت، موجودی و سند را درست برگرداند.
- [ ] چاپ با انتخاب ستون و قالب، بدون خروج از فرم.
