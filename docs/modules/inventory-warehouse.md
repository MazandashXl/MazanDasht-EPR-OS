## ۱. ماهیت موجودی در این صنعت

موجودی مازندشت سه شکل هم‌زمان دارد و هر سه باید با هم درست باشند:

| شکل | واحد | نمونه | خطر |
|---|---|---|---|
| **وزنی** | کیلوگرم | ۱۷٬۵۰۴٫۷۶۰ kg پرتقال تامسون در سردخانه ۳ | خشکیدگی و افت وزن با گذر زمان |
| **شمارشی** | عدد | ۱٬۵۰۰ کارتن، ۲۱۰ سبد، ۲۴ پالت | گم شدن، شکستگی، امانی |
| **ردیابی** | لات | `LOT-14040718-003` از باغ رضایی | نبود ردیابی در صورت شکایت مشتری |

**اصل:** موجودی، نتیجه جمع حرکات است؛ نه عددی که کسی وارد می‌کند. عدد قابل ویرایش، فساد است.

### ۲.۱ `inv_stock_move` — قانون اساسی انبار

| فیلد | نوع | توضیح |
|---|---|---|
| `id` | uuid | — |
| `move_no` | varchar(32) | `WH-04-00231` |
| `move_type` | smallint | `IN_PURCHASE`, `IN_PRODUCTION`, `OUT_SALES`, `OUT_PRODUCTION`, `TRANSFER_OUT/IN`, `ADJUST`, `RETURN_IN/OUT`, `WASTE` |
| `warehouse_id`, `cold_room_id`, `location_id` | uuid | مکان |
| `item_id`, `lot_id` | uuid | کالا و لات |
| `qty` | numeric(14,3) | واحد پایه (kg یا عدد) |
| `uom_id` | uuid | واحد |
| `unit_cost` | numeric(20,4) | بهای واحد (برای ارزش‌گذاری) |
| `business_date`, `posted_at` | — | تاریخ کاری و ثبت |
| `source_type`, `source_id` | varchar, uuid | سند مبدأ (قبض، فاکتور، حواله) |
| `is_reversal`, `reversal_of_id` | — | برگشت |
| `status` | smallint | `DRAFT/APPROVED/POSTED/REVERSED` |
| `created_by` | uuid | — |

**قواعد:**
- حرکت `POSTED` هرگز حذف/ویرایش نمی‌شود (اصل ۳).
- `TRANSFER` = دو ردیف متقارن با `transfer_group_id`.
- هیچ حرکتی بدون `source_type` و `source_id` ثبت نمی‌شود (اصل ۲).

```sql
CREATE TABLE inv_stock_move (
  id uuid PRIMARY KEY,
  move_no varchar(32) NOT NULL,
  branch_id uuid NOT NULL,
  move_type smallint NOT NULL,
  warehouse_id uuid NOT NULL REFERENCES core_warehouse(id),
  cold_room_id uuid REFERENCES inv_cold_room(id),
  location_id uuid REFERENCES inv_location(id),
  item_id uuid NOT NULL REFERENCES core_item(id),
  lot_id uuid REFERENCES inv_lot(id),
  qty numeric(14,3) NOT NULL,
  uom_id uuid NOT NULL REFERENCES core_uom(id),
  unit_cost numeric(20,4) NOT NULL DEFAULT 0,
  business_date date NOT NULL,
  status smallint NOT NULL DEFAULT 0,
  source_type varchar(64) NOT NULL,
  source_id uuid NOT NULL,
  transfer_group_id uuid,
  reversal_of_id uuid REFERENCES inv_stock_move(id),
  created_by uuid NOT NULL,
  created_at timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT ck_move_qty CHECK (qty <> 0)
);
CREATE INDEX ix_move_stock ON inv_stock_move (item_id, warehouse_id, business_date);
```

## ۳. لات و ردیابی (Traceability)

### ۳.۱ ایجاد لات

| منبع | زمان ایجاد | اطلاعات |
|---|---|---|
| قبض باسکول ورود | لحظه ثبت قبض | باغ، باغدار، رقم، تاریخ برداشت، وزن، افت |
| تولید/بسته‌بندی | با مصرف اولین لات | لات والد + خط + تاریخ |
| خرید کارتن | رسید خرید | تأمین‌کننده، سری، تاریخ |
| برگشت از فروش | با ارجاع به فاکتور | مشتری، دلیل |

```
LOT-14040718-003  (تامسون، باغ رضایی، 17,504.760 kg, 18,000/kg)
      │
      ├── سورت/بسته‌بندی → LOT-P-14040719-011  (16,650 kg, 24,000/kg)
      │        │
      │        ├── فروش S14-002381 (Tehran) 5,000 kg
      │        └── فروش S14-002395 (Karaj)   3,000 kg
      │
      └── ضایعات 600 kg
```

**قابلیت لازم:** از کد لات روی کارتن، در < ۵ ثانیه به باغ، تاریخ برداشت، خط بسته‌بندی، و مشتری برسیم. این پاسخ به شکایت «کیفیت بار» است.

### ۳.۲ کد لات روی بسته
`LOT-YYMMDD-NNN` + کد محصول + درجه؛ چاپ روی کارتن با QR (قالب چاپ `PRT-CARTON-01`).

## ۴. فرآیندها

### ۴.۱ ورود بار

```
قبض باسکول WEIGHED ──► حواله ورود خودکار ──► انتخاب سردخانه/اتاق ──► POSTED
```

پیشنهاد خودکار اتاق بر اساس: رقم + دما + ظرفیت خالی + تاریخ ورود (FIFO برای خروج).

### ۴.۲ انتقال

| انتقال | رفتار مالی |
|---|---|
| بین انبارهای یک شعبه | بدون سند (JE-INV-002) |
| بین سردخانه‌ها | بدون سند، انتقال بهای واحد با لات |
| بین شعبه‌ها | سند فروش داخلی/انتقالی (خارج از دامنه ۱.۰ — ADR باز) |

### ۴.۳ خروج (فروش)

```
فاکتور POSTED ──► حرکت OUT_SALES از لات انتخابی ──► کاهش موجودی سردخانه
```
پیشنهاد لات: FIFO بر اساس `received_date`؛ قابل تغییر با دلیل (مثلاً لات با کیفیت بهتر برای مشتری خاص).

### ۴.۴ شمارش دوره‌ای

```
ایجاد برگه شمارش (انتخاب انبار/کالا) ──► شمارش با تبلت/کاغذ ──► مقایسه
   ├─ اختلاف ۰ → تأیید
   └─ اختلاف ≠ ۰ → دلیل + مجوز ──► سند تعدیل (JE-INV-001) + حرکت ADJUST
```

| آستانه | مجوز |
|---|---|
| اختلاف < ۰٫۵٪ | سرپرست انبار |
| ۰٫۵٪ تا ۱٪ | سرپرست انبار + مالی |
| > ۱٪ | مدیر مالی + گزارش ویژه |

**قاعده شمارش کور:** شمارشگر موجودی دفتری را نمی‌بیند (جلوگیری از تأیید تعصبی).

### ۴.۵ ضایعات

| علت | مرحله | مدارک |
|---|---|---|
| پوسیدگی | سردخانه | عکس + وزن |
| آسیب مکانیکی | حمل/تخلیه | عکس + راننده |
| افت سورت | خط سورت | گزارش خط |
| انقضا/کهنگی | سردخانه | تاریخ ورود لات |

ثبت: حرکت `WASTE` + علت + عکس. بدون خط حسابداری (سیاست ۱.۰)، اما در `KPI-WST` محاسبه می‌شود.

### ۴.۶ رزرو

```
سفارش تأییدشده → رزرو به مدت N روز (پیش‌فرض ۳)
   ├─ فاکتور صادر شد → رزرو مصرف
   ├─ منقضی شد → آزادسازی خودکار
   └─ لغو سفارش → آزادسازی دستی
```
`available = on_hand − reserved`

| کد | صفحه | نکته |
|---|---|---|
| `SCR-INV-DASH` | داشبورد موجودی | کارت‌های وزنی/شمارشی، هشدار حداقل موجودی |
