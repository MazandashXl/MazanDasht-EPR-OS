# شبکه، آفلاین و همگام‌سازی

سند مرجع: `MD-NET-001` · نسخه ۱.۰ · مالک: مهندس شبکه · بازبین: معمار ERP

---

## ۱. واقعیت سایت

| واقعیت | پیامد طراحی |
|---|---|
| اینترنت ناپایدار یا قطع در ساعات کاری | سرور و کلاینت‌ها باید در LAN کار کنند |
| برق ناپایدار | UPS روی سرور و باسکول + WAL + تراکنش اتمیک |
| چند ساختمان (سردخانه، سالن، دفتر) | کابل/فیبر داخلی + Access Point |
| اپراتور با تبلت در انبار و سردخانه | وب‌اپ پاسخ‌گو + آفلاین کش |
| مدیر در سفر | دسترسی از راه دور با VPN |
| Win7 روی چند دستگاه قدیمی | Electron 22 + محدودیت‌ها (ADR-0003) |

## ۳. الزامات شبکه

| موضوع | مقدار |
|---|---|
| پورت‌های باز | ۴۴۳ (HTTPS)، ۸۰ (ریدایرکت) |
| پورت دیتابیس | ۵۴۳۲ فقط `localhost` یا VLAN سرور |
| سرعت | حداقل ۱۰۰Mbps سوییچ، ۱GbE پیشنهادی |
| تأخیر | < ۵ms در LAN |
| Wi-Fi سردخانه | برد کافی، AP صنعتی با تحمل سرما؛ حداقل ۲ AP برای پوشش |

| IP سرور | ثابت (رزرو DHCP) |
| نام داخلی | `erp.mazandasht.local` در DNS داخلی |

## ۴. حالت آفلاین

### ۴.۱ سطوح

| سطح | کجا | داده محلی | قابلیت |
|---|---|---|---|
| **L1 — دسکتاپ عملیاتی** | باسکول، انبار | SQLite کامل | کار کامل، همگام‌سازی |
| **L2 — PWA** | تبلت/موبایل | IndexedDB/SQLite (WASM) | ثبت محدود، صف ارسال |
| **L3 — مرورگر دفتری** | دفتر | کش خواندنی | مشاهده؛ ثبت نیازمند اتصال |

### ۴.۲ چه چیزی آفلاین قابل ثبت است

| عملیات | L1 | L2 | ملاحظه |
|---|---|---|---|
| قبض باسکول | ✅ | ✅ | شماره موقت |
| حواله انبار | ✅ | ✅ | کنترل موجودی محلی |
| شمارش انبار | ✅ | ✅ | ادغام پس از همگام‌سازی |
| پیش‌فاکتور | ✅ | ✅ | — |
| فاکتور فروش | ✅ | ◐ | کنترل اعتبار تقریبی؛ سرور نهایی می‌کند |
| ثبت سند حسابداری | ◐ | ❌ | فقط با قاعده محلی، بدون بستن دوره |
| بستن دوره | ❌ | ❌ | نیازمند سرور |
| Import بانک | ❌ | ❌ | نیازمند سرور |

### ۴.۳ پروتکل همگام‌سازی

```
کلاینت: POST /api/v1/sync/push
{
  "node_id": "WB-01",
  "client_time": "2026-10-10T06:12:44Z",
  "changes": [
    { "seq": 1201, "entity": "wb_ticket", "op": "insert", "id": "0192...", "payload": {...}, "idempotency_key": "wb:WB-01:1201" },
    { "seq": 1202, "entity": "inv_stock_move", "op": "insert", "id": "0192...", "payload": {...} }
  ]
}
→ 200 { "applied": 2, "rejected": [], "server_revision": 44821, "code_map": {"wb_ticket:0192...": "1404-07-18-WB-0042"} }
```

| قاعده | جزئیات |
|---|---|
| اتمیک بودن مجموعه | تغییرات یک سند (سرآمد + خطوط + حرکت انبار) در **یک change-set** |
| ترتیب | `seq` یکنوا؛ سرور خارج از ترتیب اعمال نمی‌کند |
| تکرار | `idempotency_key` یکتا؛ اعمال دوباره، نتیجه یکسان |
| شماره‌گذاری | کد موقت گره در سرور به کد نهایی نگاشت می‌شود (`core_code_map`) |
| تداخل شماره روزانه | سرور شماره نهایی می‌دهد؛ موقت برای چاپ محلی استفاده می‌شود |
| Pull | `GET /sync/pull?since_revision=N` با صفحه‌بندی |
| حجم | فشرده‌سازی gzip؛ فایل‌ها با صف جدا و Resumable |
| نمایش | وضعیت در نوار: 🟢 آنلاین · 🟡 محلی · 🔴 آفلاین (n در صف) |

### ۴.۴ حل تعارض

| موجودیت | سیاست |
|---|---|
| قبض باسکول | هرگز ادغام نمی‌شود؛ اگر همان `id` هست، نسخه محلی به صف بازبینی |
| فاکتور فروش | سرور برنده + نسخه محلی ذخیره برای بازبینی |
| حرکات انبار | همه حرکات حفظ می‌شوند (Ledger)؛ تداخل با کنترل موجودی حل می‌شود |
| CRM/یادداشت | ادغام فیلدی (آخرین تغییر هر فیلد) |
| تنظیمات | سرور برنده |

**صف بازبینی:** `sys_sync_conflict` با نمایش دو نسخه و انتخاب کاربر مجاز.

### ۴.۵ پایش سلامت همگام‌سازی

| شاخص | هشدار |
|---|---|
| صف > ۱۰۰ آیتم | زرد |
| صف > ۵۰۰ آیتم یا > ۲ ساعت | قرمز + نوتیفیکیشن IT |
| خطای تکراری ارسال | قرمز |
| آخرین همگام‌سازی > ۲۴ ساعت | قرمز |

## ۵. دسترسی از راه دور

```
[کاربر] ──TLS──► [VPN WireGuard] ──► [سرور ERP]
                     │
                     ├─ احراز دو مرحله‌ای
                     ├─ محدودیت IP (اختیاری)
                     └─ لاگ کامل
```

| قاعده | جزئیات |
|---|---|
| هیچ پورت دیتابیس به اینترنت باز نمی‌شود | — |
| VPN با کلید + 2FA | — |
| دسترسی موبایل | همان PWA روی HTTPS با گواهی معتبر |
| نشست | ۱۵ دقیقه بی‌کاری → قفل |

## ۶. نصب آفلاین (بدون اینترنت)

| نیاز | راهکار |
|---|---|
| بسته نصب .NET/PostgreSQL | بسته خودکفا (`installer/offline-bundle`) |
| وابستگی‌های npm | `npm pack` + کش محلی یا build در محیط متصل |
| گواهی TLS | CA داخلی یا self-signed توزیع‌شده |
| به‌روزرسانی | بسته `.zip` با امضا، نصب دستی/اسکریپت |
| فونت‌ها | همراه بسته |

## ۷. پذیرش

- [ ] قطع اینترنت: همه عملیات LAN ادامه دارد.
- [ ] قطع کامل شبکه: باسکول و انبار ۸ ساعت کار می‌کنند.
- [ ] پس از اتصال: صفر داده گم‌شده، صفر رکورد تکراری.
- [ ] تداخل همگام‌سازی، داده را حذف نمی‌کند و در صف بازبینی دیده می‌شود.
- [ ] هیچ پورت دیتابیسی از خارج LAN قابل دسترسی نیست.
- [ ] همگام‌سازی ۵۰۰ رکورد در < ۳۰ ثانیه روی LAN.
