## ۴. ماتریس SoD (تعارض‌های ممنوع)

| نقش ۱ | نقش ۲ | تعارض |
|---|---|---|
| SALES | TREASURY | تعیین قیمت + دریافت پول |
| PURCHASING | TREASURY | تعیین خرید + پرداخت |
| WAREHOUSE | ACCOUNTANT | شمارش + تأیید تعدیل مالی |
| ACCOUNTANT | FIN_MANAGER | ثبت + تأیید (در شرکت‌های کوچک قابل استثنا با لاگ) |
| HR | FIN_MANAGER | تعیین حقوق + پرداخت |
| SYS_ADMIN | هر نقش مالی | تغییر مجوز + استفاده |

**سیاست:** در نصب‌های کوچک با کمتر از ۵ کاربر، تعارض‌ها با «مجوز استثنا» و گزارش ماهانه فعال می‌شوند، اما سیستم هشدار می‌دهد.

## ۵. پیاده‌سازی

```sql
CREATE TABLE sys_role (
  id uuid PRIMARY KEY,
  code varchar(40) NOT NULL UNIQUE,
  name_fa varchar(120) NOT NULL,
  is_system boolean NOT NULL DEFAULT false
);

CREATE TABLE sys_role_permission (
  role_id uuid NOT NULL REFERENCES sys_role(id),
  permission varchar(80) NOT NULL,
  amount_limit numeric(20,4),
  PRIMARY KEY (role_id, permission)
);

CREATE TABLE sys_user_role (
  user_id uuid NOT NULL,
  role_id uuid NOT NULL,
  branch_id uuid,
  valid_from date,
  valid_to date,
  PRIMARY KEY (user_id, role_id, branch_id)
);
```

- نقش‌های سیستمی قابل حذف نیستند؛ قابل کلون.
- تغییر مجوز نقش، اثر فوری (کش مجوز ۶۰ ثانیه‌ای).
- هر تغییر، در `sys_audit_log` ثبت می‌شود.
- مجوزها در JWT **نگه داشته نمی‌شوند**؛ در هر درخواست از کش سرور خوانده می‌شوند تا ابطال فوری ممکن باشد.

## ۶. پذیرش

- [ ] هر نقش پیش‌فرض، حداقل یک کاربر آزمون دارد و همه ماتریس تست شده.
- [ ] تعارض SoD در سطح API و UI اعمال می‌شود.
- [ ] سقف مبلغ، در سرور اعمال می‌شود (نه فقط UI).
- [ ] تغییر نقش کاربر، در ≤ ۶۰ ثانیه اثر کند.
- [ ] گزارش «چه کسی چه مجوزی دارد» یک‌کلیکی است.
