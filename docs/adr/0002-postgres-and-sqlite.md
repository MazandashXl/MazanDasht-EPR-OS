# ADR-0002 — PostgreSQL اصلی + SQLite برای آفلاین

- تاریخ: ۱۴۰۴/۰۸/۰۲ · وضعیت: **Accepted**
- تصمیم‌گیرندگان: معمار ERP، مهندس شبکه
- مرتبط: ARC-03، REQ-N-005، REQ-F-010

## زمینه
سرور نیازمند دقت عددی، تراکنش، ویو، پارتیشن و کارایی گزارش است. کلاینت‌های میدانی نیازمند کار آفلاین بدون سرور هستند.

## گزینه‌ها
1. PostgreSQL 16 (سرور) + SQLite (کلاینت)
2. PostgreSQL در هر دو (نیازمند سرور محلی سنگین روی هر ایستگاه)
3. SQLite در همه‌جا (ناتوان در همزمانی و گزارش سنگین)
4. SQL Server (لایسنس، وزن استقرار)

## تصمیم
PostgreSQL 16 سرور؛ SQLite 3.45+ فقط در کلاینت‌های آفلاین‌پذیر. مدل داده یکی است؛ مایگریشن‌ها برای هر دو پلتفرم تولید می‌شوند؛ یکپارچگی مالی (NUMERIC، Constraint) در هر دو پیاده می‌شود.

## پیامدها
- مثبت: کارایی و دقت سرور + آفلاین سبک.
- منفی: دو مسیر مایگریشن و دو مجموعه تست؛ تفاوت رفتار Trigger بین دو موتور.
- کاهش ریسک: قواعد حساس در لایه APPLICATION نیز تکرار می‌شوند (دفاع لایه‌ای).
- بازبینی: اگر SQLite نتواند قواعد را پوشش دهد، کلاینت آفلاین به «صف رویداد بدون اعتبارسنجی محلی» تغییر می‌کند.
