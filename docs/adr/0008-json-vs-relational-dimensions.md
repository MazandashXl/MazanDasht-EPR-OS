# ADR-0008 — ابعاد تحلیلی رابطه‌ای به‌جای JSON

- تاریخ: ۱۴۰۴/۰۸/۰۲ · وضعیت: **Accepted**
- تصمیم‌گیرندگان: معمار ERP، متخصص علم داده
- مرتبط: BR-*، KPI-*

## زمینه
سند نیازمند ابعاد متعدد (باغ، سردخانه، مرکز هزینه، پروژه، خودرو، پرسنل) است. JSONB انعطاف دارد اما گزارش‌گیری و یکپارچگی را ضعیف می‌کند.

## گزینه‌ها
1. ستون‌های JSONB برای ابعاد.
2. ستون‌های مشخص (`garden_id`, `cold_room_id`, ...) + جدول `fin_line_dimension` برای ابعاد آزاد.
3. EAV کامل.

## تصمیم
گزینه ۲: شش بُعد پرکاربرد به‌صورت ستون FK (سریع، ایندکس‌پذیر، دارای یکپارچگی)، حداکثر ۳ بُعد آزاد در `fin_line_dimension` با نوع کنترل‌شده. JSONB فقط برای Snapshot و Payloadهای غیرتحلیلی.

## پیامدها
- مثبت: گزارش سریع، FK معتبر، ایندکس مؤثر.
- منفی: افزودن بُعد جدید = مایگریشن (نه تغییر تنظیمات).
- قاعده: بُعد جدید فقط با ADR و پس از اثبات نیاز در ۳ گزارش.
