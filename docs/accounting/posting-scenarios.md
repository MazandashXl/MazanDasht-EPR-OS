سند مرجع: `MD-ACC-003` · نسخه ۱.۰ · مالک: حسابرس مالی ارشد · بازبین: متخصص صنعت

هر سناریو یک کد `JE-…`، یک رویداد محرک، و خطوط دقیق بدهکار/بستانکار دارد. **این جدول‌ها قرارداد بین صنعت و حسابداری‌اند:** اگر عددی در این سند نباشد، در کد هم نباید باشد.

نمادها: `Dr` بدهکار · `Cr` بستانکار · `[بُعد]` ابعاد تحلیلی اجباری.

## ۱. نمونه مرجع (Canonical Numbers)

همه مثال‌های این سند بر پایه این محموله است تا اعداد قابل مقایسه باشند.

| پارامتر | مقدار |
|---|---|
| کامیون | `27,650 kg` وزن پر، `9,200 kg` وزن خالی → وزن بار **`18,450 kg`** |
| سبد | ۲۱۰ عدد سبد قرمز × `2.8 kg` = **`588 kg`** |
| افت بار | ۲٪ روی `17,862 kg` = **`357.240 kg`** |
| وزن خالص خرید | **`17,504.760 kg`** |
| فی خرید | `18,000 ریال/kg` → مبلغ خرید **`315,085,680 ریال`** |
| خروجی بسته‌بندی | `16,650 kg` (۱٬۰۰۰ کارتن ۵ کیلویی + …)، ضایعات `600 kg`، سایر افت `254.760 kg` |
| بهای تبدیل | دستمزد `22,000,000` + کارتن `52,500,000` + انرژی `8,000,000` + سردخانه `2,014,320` = **`84,514,320`** |
| بهای تمام‌شده لات | `315,085,680 + 84,514,320` = **`399,600,000`** → `24,000 ریال/kg` |
| فروش | `5,000 kg` × `320,000 ریال` = **`1,600,000,000`** |

## JE-PRD-002 — ضایعات

سیاست نسخه ۱.۰: **ضایعات با ارزش صفر در بهای تمام‌شده** ثبت می‌شود؛ یعنی هزینه ضایعات در بهای محصول سالم جذب شده است. بنابراین:

- هنگام ثبت ضایعات: فقط مقدار (`inv_stock_move` با نوع `WASTE`) ثبت می‌شود، بدون خط حسابداری.
- هنگام فروش ضایعات: کل مبلغ فروش، درآمد است (`4103`)، بدون COGS.

> اگر در آینده سیاست «ارزش‌گذاری ضایعات به ارزش خالص فروش» انتخاب شود، JE جدید `JE-PRD-003` لازم است (ADR باز).

## ۱۰. قاعده ثبت چندخطی و دوباره‌شماری

| وضعیت | تصمیم |
|---|---|
| فروش + COGS + مالیات | **یک سند** با ۹ خط |
| خرید + حمل سرمایه‌شده + تهاتر پیش‌پرداخت | **یک سند** |
| بسته‌بندی + مصرف کارتن + دستمزد | **یک سند** |
| دریافت چک + انتظامی | **یک سند** با ۴ خط (۲ خط مالی + ۲ خط انتظامی) |
| دریافت نقدی + تخفیف + تهاتر | **یک سند** |
| تعدیل انبار + تعدیل بهای تمام‌شده | **دو سند** (یکی موجودی، یکی بهای تمام‌شده) — چون رویدادها جدا هستند |

## ۱۱. پیکربندی قاعده (نمونه YAML ذخیره‌شده در `fin_posting_rule`)

```yaml
code: JE-SAL-001
event: sal.invoice.posted
version: 1
effective_from: 1404-01-01
when: "invoice.status == 'POSTED'"
lines:
  - side: DR
    account: "{{party.receivable_account_id | default: acc.receivable.market_trader}}"
    amount: "invoice.net_payable"
    party: "{{invoice.party_id}}"
    dims: [branch, channel]
  - side: DR
    account: "{{deduction.account_id}}"
    amount: "{{deduction.amount}}"
    foreach: "invoice.deductions"
    filter: "type == 'PURITY'"
    dims: [cost_center]
  - side: CR
    account: "{{invoice.sales_account_id | default: acc.sales.default}}"
    amount: "invoice.gross_amount"
    dims: [branch, item, lot, cold_room]
check:
  - balance: "abs(total_debit - total_credit) <= 0.01"
  - required_dim: [branch, lot]
```
