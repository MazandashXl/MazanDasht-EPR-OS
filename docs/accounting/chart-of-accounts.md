# ساختار حساب‌ها (Chart of Accounts)

سند مرجع: `MD-ACC-002` · نسخه ۱.۰ · مالک: حسابرس مالی ارشد · تأیید: معمار ERP

---

## ۱. فلسفه کدینگ

دو خطر متضاد وجود دارد:

| خطر | نتیجه | راهکار |
|---|---|---|
| حساب‌های زیاد و ریز | دفتر کل غیرقابل خواندن، هر مشتری یک حساب → ۵٬۰۰۰ حساب | استفاده از **ابعاد تحلیلی** به‌جای حساب جدید |
| حساب‌های کم و کلی | عدم امکان تحلیل، «هزینه‌های متفرقه» غول‌آسا | معین کافی برای هر نوع هزینه واقعی مازندشت |

**قاعده تصمیم: حساب یا بُعد؟**

| اگر … | آنگاه |
|---|---|
| می‌خواهیم در ترازنامه/سود و زیان خط مستقل داشته باشد | **حساب** |
| فقط برای تحلیل مدیریتی است (باغ، سردخانه، مشتری) | **بُعد** |
| طرف حساب است (مشتری، باغدار، بانک) | **تفصیلی** زیر حساب معین مربوط |
| هر سال تغییر می‌کند (پروژه، قرارداد) | **بُعد** |

## ۲. ساختار سطوح

```
سطح ۱ — گروه      4 گروه اصلی + انتظامی        کد ۱ رقمی     : 1
سطح ۲ — کل        4 رقمی (گروه + ۳ رقم)                     : 1101
سطح ۳ — معین      5 رقمی                                    : 11031
سطح ۴ — تفصیلی    9 رقمی (طرف حساب/بانک/شعبه)               : 110310001
```

| سطح | قابل ثبت؟ | مثال |
|---|---|---|
| گروه | ❌ | `1` دارایی‌ها |
| کل | ❌ | `1101` صندوق |
| معین | ❌ (مگر بدون تفصیلی) | `11021` بانک ملت |
| تفصیلی | ✅ | `110210001` بانک ملت — جاری اصلی |

**قواعد:**
- فقط حساب برگ (`is_leaf = true`) قابل ثبت است؛ سرفصل هرگز.
- حساب دارای گردش قابل حذف نیست؛ فقط غیرفعال.
- ماهیت (`nature`) از والد به ارث می‌رسد و تغییر آن ممنوع است.
- حساب‌های ارزی، `currency_id` دارند و مانده‌شان به ارز اصلی هم نگه داشته می‌شود.
